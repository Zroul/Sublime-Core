## Current guardrails

- Transcription accepts only registered CEP extension IDs with Adobe CEP request metadata and the observed CEP `file://` origin (or an opaque `null` origin); audio is not sent to Ollama or a hosted speech service.
- The model downloader is used only for the explicitly authorized base checkpoint. Runtime transcription verifies the cached SHA-256 and fails closed for a missing or corrupt model.
- Ollama is checked but never started, restarted, or duplicated by OBSIDIAN.
- The installer target is the isolated smoke directory with its unique CEP identity. The main extension remains untouched.

## 2026-10-31 CEP transcription authorization

- **Live diagnosis verified:** one request from the installed isolated Smoke panel reached `POST /transcribe`. Sanitized server diagnostics recorded `Origin: file://`, `Content-Type: application/json`, `Sec-Fetch-Site: cross-site`, `Sec-Fetch-Mode: cors`, and an Adobe CEP user agent. CEP omitted `Referer`. The request was rejected before the transcription worker ran.
- **Root cause:** both server and handler required `request.headers.origin === "null"`. The local unit-test request helper supplied `null`, while this CEP 12 / Chromium 99 runtime sends `file://`.
- **Fix implemented in source:** frontend sends the runtime extension ID from `__adobe_cep__.getExtensionId()`. The backend requires an allowlisted OBSIDIAN panel ID, Adobe CEP user agent, CORS fetch mode, and `file://` or `null` origin. The preflight allows only that CEP transport and the required headers; responses echo the accepted CEP origin. Ordinary web origins and unmarked callers remain rejected.
